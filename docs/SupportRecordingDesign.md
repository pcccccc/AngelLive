# 诊断录制交互 · 第二轮

范围：用户明确选择先重做「记录过程（开始、计时、结束）」，覆盖 iOS/iPadOS、macOS、tvOS FullUI。报告编辑及分享页另行设计，不把本轮录制验收当作整页验收。后续 TV 报告、描述编辑和预览下载的设计见 [TV 报告规范](SupportTVReportDesign.md)，下文录制轮次的范围说明仅描述该轮交付。

## 参考与语义

SwiftUX MCP 返回 `kind: component`、`id: audio-input-bar`，置信度 high。已读取 `get_conventions`、`get_component` 和 `get_component_source`。来源：[Audio Input Bar](https://www.swiftux.app/uicomponents/audio-input-bar)，实际源码类型 `VoiceInputBar`。

采用其「状态、计时、开始/结束控制集中在同一条录制面板」结构。诊断不录音，不能移植假波形、麦克风权限、累加式 Timer 或示例黑白硬编码配色。计时来自服务的 `startedAt` 与系统时间，使用现有 TimelineView；结束后仍由服务生成报告。

Xcode MCP 的 Apple 文档查询补充：Form 的平台分组不同；macOS cancellationAction 进入 sheet 操作栏；tvOS focusSection 依靠容器几何引导到可聚焦子项，不使整个容器可聚焦。实施同时依据 PRODUCT.md、axiom-design/HIG、axiom-swiftui/layout、axiom-macos 和 tvOS focus 指南。

## 带尺寸的布局参考

### iPhone / 窄 iPad（内容宽度随容器，最多 560 pt）

```text
导航：问题诊断与反馈
┌──────────────────────────────┐
│ 记录一次问题                 │ title2 / semibold
│ 开始后，回到出现问题的页面。   │ body / secondary，最多自然两行
│                              │ 24 pt
│ ┌──────────────────────────┐ │ 圆角 20；语义次级背景；内边距 16
│ │ [诊断]  准备记录   [ ● ]  │ │ 状态 headline；控制宽 96、最小高 64
│ │         00:00     开始记录│ │ 数字 largeTitle / monospaced
│ │ ──────────────────────── │ │ 细进度 3–4 pt
│ │ 最长 5 分钟 · 结束后生成报告│ │ caption / secondary
│ └──────────────────────────┘ │ 面板不低于 136 pt
│                              │ 24 pt
│ ↩ 返回原页面                 │ 两条紧凑指引，图标 + 标题/说明
│   按平时的方式重现问题。       │ 组内间距 16 pt
│ ▣ 回来结束记录               │
│   检查报告后，自行选择分享。   │
│                              │
│ ⓘ 记录哪些信息               │ 展开后说明真实采集范围
└──────────────────────────────┘
左右 20 pt，段落间 24 pt。

记录中：同一位置显示「正在记录 / 00:37 / ■ 结束记录」。
面板下出现「返回并复现」主要操作；开始/结束控制不移动位置。
```

开始和记录状态使用相同结构、面板尺寸和计时位置；去掉这两个状态的顶部三步进度条。计时旁不另堆红色大标题。页面返回不会停止录制。

### macOS（内容上限 560 pt）

复用同一录制面板，内容左右 24 pt、上方 20 pt；面板高约 128 pt。说明区使用紧凑的两行说明布局，不把所有文字放大。返回按钮按内容宽度布局（约 160 pt），不要整窗铺满。宿主关闭入口位于工具栏右侧；录制过程无需额外厚重底栏。键盘和鼠标都可激活具名开始/结束按钮，点击区域至少 44 pt。

### TV 原有样式对齐（2026-09-18 后续修正）

用户要求诊断录制页与既有 TV 页面保持视觉一致，尤其不能混用不同宽高的按钮。视觉来源为 `TV/AngelLiveTVOS/Source/Setting/SettingView.swift` 的 `menuListView`：左右半屏、右栏宽为容器宽的一半减 50 pt，按钮为 `HStack(spacing: 15)` 横向整行，使用系统默认按钮样式和字号，行间 15 pt。不能拿通用设置中 Toggle 的 45 pt 外框作为按钮高度。

SwiftUX 本次再次核对了已有 `audio-input-bar` 的适配契约：仅参考结构，颜色、字体及外观必须服从目标应用；不再搜索另一个录制组件。

```text
导航标题：问题诊断与反馈（高对比语义文字）
┌ 左半屏：说明与真实计时 ─────────┬ 右半屏：原生操作行 ──────────────┐
│ 记录一次问题                    │ 开始记录／结束记录          ●/■ │
│ 简短的操作说明                  │                                 │ 15 pt 行间
│                                │ 返回并复现                    ↩ │ 仅记录中
│ 准备记录／正在记录              │                                 │
│ 0:37                           │ 接下来：返回原页面复现，回来结束。│
│ ───────── 五分钟进度            │ 仅在本机保存 · 分享前可检查       │
└────────────────────────────────┴─────────────────────────────────┘
```

- 录制与返回共用一个 TV 原生操作行组件：文字靠前、符号靠后、水平排列、相同 body 字号、同一列宽、相同系统内边距和自然行高。移除 180/320 pt 独立宽度、72/60 pt 独立最小高度及 large controlSize。最终比较 hierarchy 的真实按钮 frame，而非声称 frame 修饰符等于可见外框。
- 左右分栏宽度取最近 ScrollView 的容器宽度各一半，右栏尾部 50 pt，左栏水平内边距 90 pt。TV capture 的外层不再叠加 1400 pt 宽限制和 90 pt 水平内边距。报告态维持本轮之前布局。
- 计时为独立的 TV 状态区域，不再复用带窄竖向按钮的手机录制面板。继续以 startedAt + TimelineView 同步时长与进度，沿用五分钟上限和现有服务回调。
- 开始与结束保持在第一行原位切换；记录中第二行显示返回并复现，并默认聚焦第二行；上键可到结束，下键可回返回。正常焦点高亮、前景色、材质和放大交给系统，不自绘按钮样式。
- Preview 的 TV 容器必须使用与实际宿主相同的深色模式、横向布局和导航环境，避免提供标题发黑的错误预览。
- TV 页面与 Preview 使用原生 principal ToolbarItem 承载相同的 SwiftUI 标题，标题视图采用 headline、深色环境下的语义 Color.primary 和标题无障碍特征；保留 navigationTitle 语义。系统栏颜色偏好在已取得的 Preview 中未改善标题对比，最终实现不保留无效的背景／颜色偏好补丁。状态文字与「接下来」均为 headline，低于左侧页面主标题。
- 两个 TV FullUI 宿主既有诊断 NavigationStack 的 `.preferredColorScheme(.dark)` 保持不变；该范围以外沿用宿主原有外观设置。
- 仅改 TV 条件分支及 TV 组件；iOS/macOS、报告编辑/分享、诊断服务及 ShellUI 不在本次修正范围。

验收：实际设置页原图作为基线；最后编辑后的 TV MCP BuildProject/error issues、InstallAndRun；原生按钮未聚焦时同宽同高，聚焦后两行采用同等缩放；开始→计时增长→返回→重入→结束；导航标题可读、焦点不裁切。不能只用 Preview 代替遥控器流程。

## 反馈与边界

- 开始成功才显示计时；失败保留可重试入口并就近显示原服务错误。
- 控制图形由圆点切换为方形，计时数字使用短的 numericText 过渡；尊重减少动态效果，不使用持续闪烁、随机音量条或假诊断活动。
- 字体与颜色采用系统语义；面板内层级通过字号、位置、留白区分，不用多个绿色勾选表示录制成功。
- iOS/macOS 开始/结束操作使用 subheadline semibold 和明确的 `Color.primary`，避免在按钮内部把层级样式 `.primary` 解析成浅色强调色；tvOS 按上文使用 body 与系统焦点前景色。当前宿主的珊瑚强调色 `#FF815E` 与白字对比约 2.46:1，因此 iOS/macOS 返回主操作采用深色字（约 8.55:1），深浅色均保持可读。
- 停止后进入已有报告态，录制时长/内容仍由服务提供，不插入假“处理中”或延迟。
- 保持已有 startRecording / stopRecording / onReturn 回调语义，不改服务、报告格式、五分钟上限、ShellUI 或插件数据。
- 原有报告存在时，重新记录的确认仍生效。初次开始不用确认；结束不用确认。

## 验收

先用 SwiftUI Preview 复核开始/记录两个状态的尺寸、对齐和深浅色，再按 AGENTS 执行最后源码修改后的三端 MCP build、新包运行与交互。实际确认开始、计时增长、返回后继续、结束生成报告；tvOS 确认焦点与遥控器返回。未完成的平台和状态明确标记，不能以布局不裁切作为全部视觉验收标准。

Preview 使用独立的无副作用容器，复现宿主的 NavigationStack、ScrollView、内容宽度及内边距；Mac 画布 640 × 560，tvOS 1920 × 1080。裸组件在默认预览大窗口中的垂直居中不代表实际页面布局。两个 Preview 声明在平台条件之外，index 0 为待开始、index 1 为记录中，避免工具按源码顺序选中被条件编译排除的声明。
