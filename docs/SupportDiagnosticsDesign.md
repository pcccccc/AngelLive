# 问题诊断与反馈界面规范

录制过程的当前设计以 [第二轮录制规范](SupportRecordingDesign.md) 为准，采用 SwiftUX `audio-input-bar` 的控件结构。TV 的报告、独立描述编辑和预览下载以 [TV 报告规范](SupportTVReportDesign.md) 为准。以下是第一轮历史参考；iOS/macOS 的报告编辑和分享仍待下一轮设计复核。

适用范围：iOS、macOS、tvOS 的 FullUI「问题诊断与反馈」。依据 `PRODUCT.md` 的原生、克制原则，以及现有三端设置页的系统背景、字体和导航。诊断服务、报告格式、脱敏和五分钟上限保持既有契约。

## 布局参考与尺寸

以下布局示意是本轮实施参考；尺寸为逻辑点。使用系统语义颜色，强调色仅用于当前步骤和主要按钮，录制状态使用红色并同时提供文字。内容区使用普通系统背景，不用多层玻璃、大面积渐变或六组相同的占位卡片。

手机内容左右留白 20，垂直段落间距 24，内容上限宽度 680；平板及 Mac 居中，窄窗口自然换行。Mac 适配现有 600 × 640 起的 sheet。所有交互目标至少 44 高，正文使用 body/callout，标题使用 title2，辅助文案使用 subheadline/caption，支持大字体换行。

```text
│ ① 开始 — ② 复现 — ③ 分享 │     │ ✓ 开始 — ✓ 复现 — ③ 分享 │

```

记录中替换中间内容：状态「正在记录」、系统驱动的等宽数字计时（上限五分钟）、进度及「返回刚才的页面，重现问题，完成后回来结束记录」。提供「返回并复现」和「结束记录」两个清楚区分的操作。页面退出不能停止记录。

tvOS 内容左右留白至少 72、上下至少 40，上限宽度 1400。开始/记录页左侧为标题、状态和主要操作（约 560 宽），右侧为三步引导（约 440 宽），间隔 64；不让说明堆出首屏。报告页左侧为摘要、补充及操作，右侧为报告预览入口及手机获取说明。正文采用 tvOS 语义字体，按钮使用系统焦点样式，间距至少 24；不可用触控坐标假设。完整预览为独立导航页面，QR 面板按需呈现。反馈页面须以不透明背景覆盖可用区域和安全区，避免宿主全屏弹层的材质透出背后彩色画面；导航标题也必须有清楚对比。

## 交互验收

- 首次进入只有可用操作，无「生成后才可用」的多组空占位。三步指示只展示进度，不伪装成可点击标签。
- 开始操作成功后才进入记录中；失败显示就近错误。显示真实开始时间驱动的计时，不增加业务 timer。返回后记录仍持续；服务自动停止后展示当前新报告。
- 重新记录需说明会替换最近报告并允许取消；当前报告在录制中不预览、不复制、不分享。
- 报告摘要来源于真实 report 的时间与数量，零条记录不能表述为检查通过。错误快照展示当前错误摘要，并提示可重新记录以收集复现过程。
- 补充描述可编辑；保存后显示明确反馈，服务返回错误时不显示成功。进入预览之前保存当前补充，并以服务脱敏后的最终 reportText 预览和分享，失败不能静默丢弃草稿。
- 完整报告进入独立可滚动预览，iOS/Mac 支持文本选择。分享操作与预览同页，提供复制确认、系统文本/文件分享；导出失败显示错误与重试，不伪造成功。不得自动上传。
- tvOS 预览需可通过遥控器聚焦与滚动；手机下载只在用户主动选择后启动既有临时服务，展示二维码、同网络要求、五分钟有效期、关闭下载。报告修改/清除/重新录制/离开分享页后停止服务。
- 清除报告保留破坏性确认，取消不改变任何状态。报告由其他入口更新时，同步新快照并使旧导出失效。
- 过渡仅使用短淡入或系统动画，尊重减少动态效果；录制状态、复制、保存都不能只靠颜色表达。深浅色、动态字体、窄窗口不裁切文字。
