# UI 视觉门禁与验收

**触发条件：新增或修改布局、字体、间距、主题、状态呈现，或进行视觉审查。** 按根 [AGENTS.md](../../AGENTS.md) 的顺序在相关操作前读取；本流程与根指南同等效力，不能绕过根文件红线。未特别说明的路径均相对仓库根目录。

1. **准备与参考**：Astra 依据 `PRODUCT.md`、目标平台 HIG 和现有界面确定页面/模式边界、信息层级、布局间距、字体颜色、交互导航及验收标准。参考须为明确的同平台页面、截图、设计稿或带尺寸示意，注明来源和适用设备，不能只说“更原生/精致”；足够的小修改可复用既有标准。
2. **分派与模型**：遵守根 §1「布局模型」「模型可用性」红线及 §2 模型分工；交付参考、标准、文件与接口后实施。模型阻塞时仍可继续不依赖该模型的工作。
3. **逐项对齐**：按根 §1「视觉对齐」的完整检查项逐项核对；光学偏差检查涵盖图标字形、留白和描边。数值相同、容器居中或修改文案不能代替截图中的实际对齐。
4. **状态清单**：实现前列明受影响页面及适用状态：长文本、动态字体、深浅色、加载/空态/错误、无障碍、产品支持的 iPhone/iPad 尺寸、横屏/分屏、macOS 窗口变化及 tvOS 焦点/遥控器。使用自适应布局，不改产品方向或窗口策略，不为单张截图固定屏幕尺寸；按影响范围验收，不扩为无关设备全组合。逐项记录“通过/不通过/阻塞/不适用”及证据，不适用须有依据。
5. **接管交接**：代码审查、设备验收或用户反馈确认视觉问题后，执行根 §1「布局模型」的 Astra 接管要求。保留其他修改与功能逻辑，交接基准、失败证据和接管状态；未通过前由 Astra 继续负责。
6. **最终验收**：按根指南验证矩阵及 [设备流程](device-hub.md)完成对应构建和最后编辑后新包的截图、交互验证。三端分别对齐各自既有页面，业务含义一致但不强行统一控件；root 按原尺寸截图逐项复核。任一同类行高度、边缘、基线或样式不符必须修复后重新验收，源码相似、编译成功、自动化断言或代理自评不能替代视觉通过。
7. **不可降低门槛**：视觉对齐同时满足业务正确性、数据安全和无障碍；不因改动小、工期、工具故障或上下文切换豁免。代理主动发现并修复问题，不让用户反复指出、不交给用户验收或留待以后美化。缺少新包证据或仍有缺陷时不得宣称完成，按根指南交付纪律报告未完成。
8. **决策与阻塞**：信息架构、交互含义和公共接口变更交回 root/Astra；上述要求不改变 FullUI/ShellUI 边界或替代 Skill。工具冲突、超时、构建/安装/登录故障只属验证阻塞，本身不触发布局重写；按[Xcode 恢复流程](xcode-mcp.md)恢复，无法恢复则记录缺失证据与恢复条件。工具阻塞不撤销已确认视觉问题的 Astra 接管要求。
