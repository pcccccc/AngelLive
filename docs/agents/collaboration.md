# 协作、交接与独立测试

**触发条件：分派或交接子代理、独立测试、监控运维、维护代理指南。** 按根 [AGENTS.md](../../AGENTS.md) 的顺序在相关操作前读取；本流程与根指南同等效力，不能绕过根文件红线。未特别说明的路径均相对仓库根目录。

以下是项目使用偏好与经验判断，可根据后续证据更新，不代表模型的固定能力边界。能由 GPT-6 系列完成的实现、排查、运维与监控，优先交给对应子代理。root 保留整体判断和最终责任，Astra 集中处理关键设计与极其复杂的问题。简单、不可拆分且没有独立并行工作的任务直接完成，不为使用代理而拆分。

### 分派、测试与交付

- 流程：root/Astra 确定目标、架构和接口 → GPT-6 子代理实现并自测 → 按风险由 Terra 独立测试 → root 复核；极其复杂或跨架构问题再由 Astra 复核。
- 分派明确目标、完成标准、文件/服务所有权、依赖及禁止范围、输入输出、已确认的类型/函数签名与语义、错误边界、验证方式。先确定接口再分派依赖它的实现；监控/运维另列步骤、时段、频率、异常和停止条件，结果附时间及证据，异常按复杂度升级。
- 同一文件修改范围和设备 session 各有唯一负责人。交接前原负责人停止操作，说明最后修改、检查结果、设备/session、阻塞及剩余工作；接手方重新核验连接和设备，不复用失效标识或旧包证据。设备操作权不等于布局修改权，视觉问题交对应代码负责人。
- 实现遵守真实契约，不虚构异常场景或扩展架构；外部输入校验、租户隔离、写入结果不确定时的处理及幂等恢复必须保留，增删防御逻辑均需代码、协议或故障证据。
- 逻辑/状态回归、公共接口和跨端行为修改，优先由 `gpt-6.1-terra / high` 独立设计正常、边界、失败和受影响回归用例，不按实现分支复写断言。root 提供需求、故障、契约、范围和测试入口；纯文档或低影响显示修改不为使用代理增设测试任务。
- 实现者负责自查、必要测试与修复。Terra 默认只改分派的测试/CI 文件；生产、架构或布局问题附最小复现交回 root，不为测试扩大 API、改写产品行为或自行取得设备 session。
- 子代理交付实际 diff、已运行检查、结果、证据及未解决项。root 独立核对代码、回归能否识别原问题、断言契约及结果对应的最终版本；实现者自评、Terra 结论、编译成功或 CI 绿灯均不能替代相应验收。

### 指南维护

Astra 作为 root 或子代理均可依据真实代码、故障和验收证据维护相关 `AGENTS.md`，无需另行确认；先协调文件所有权，子代理修改后向 root 汇报。保留适用场景、原因和有效处理结论，待验证判断明确标注，不把猜测或偶发现象写成永久禁令。根文件保留通用规则，模块细则放局部指南，长案例放 `docs/` 并链接；定期去重及清理失效经验，不扩大生产、发布或外部消息授权，不覆盖用户明确要求。
