## 分派范围与调用契约

初期优先选择能与 root 的有效工作独立并行、结果容易核验的只读任务：

- 搜索符号、调用方、配置读写点，返回有限数量的文件与行号。
- 按明确规则检查 diff 或指定文件，例如 ShellUI 边界、本地化键完整性。
- 对给定构建或测试日志提取首个有效错误、相关上下文与证据。

不为试用拆出 root 已经能直接完成的几行修改。不得把架构设计、Swift 并发、播放恢复、插件协议、凭证、跨端状态或设备 session 交给本轮试用代理。

至少取得 3 个独立任务首次交付均达 85 分、无重大问题的样本后，root 才可尝试已确认方案的小范围非 UI 修改或明确测试案例；这只是试用准入条件，不代表统计上证明可靠。修改任务使用明确的文件所有权或独立 worktree，仍遵守根指南的构建、测试和验收门禁。

每次派单记录：

1. 唯一任务 ID、当前 Codex 任务标识（可取得时）、父任务目的、首次或第几次追问。
2. 实际 Harness 版本、模型、推理设置及 CLI/ACP/MCP 调用方式；无法确认的字段写未知，禁止猜测。
3. 仓库根目录、代码版本或 diff 基准、文件范围、禁止修改项、相关项目规则与必要 Skill 内容。
4. 可逐项核验的验收清单、输出数量上限、预先确定的返回时间预算 B；没有特殊理由时，只读小任务 B 为 120 秒。预算是本次试用标准，不是性能承诺。
5. 派发、返回、复核完成时间。返回耗时 T 从发起调用到收到终态结果，包含启动、排队和工具耗时；另外记录 root 复核耗时、返工轮数及累计耗时。

运行前验证实际入口及其权限策略。只读要求不能仅靠文字保证；必须核验工具/运行环境权限或使用受限副本，并核对任务前后 diff。保留现有 Web 服务和会话，不借试用重启服务、升级依赖或绕过审批。

预算到期时先读取状态，使用已验证的取消方式终止本次调用；不得因工具等待超时就认定子进程已经停止。若尚未停止，应报告“超时、仍运行”，继续处理收尾并避免重复派单。环境失败与模型答错分别记录。

## root 独立检查与评分

先核对实际文件、引用行号、日志或必要测试，再评分；子代理自评不能替代 root 检查。只读任务不额外运行与结论无关的构建。按派单前确定的清单评分，分项四舍五入取整数，总分为五项之和。

| 维度 | 满分 | 评分方法 |
| --- | --- | --- |
| 正确性 | 40 | 40 × 验收清单中已核验正确的条目数 / 条目总数；遗漏项不算正确。清单外错误结论作为额外失败条目，记录具体原因。 |
| 完整性 | 20 | 20 × 已交付的必需项目数 / 必需项目总数；只检查是否交付，内容对错由正确性计分。 |
| 可验证证据 | 15 | 15 × 证据有效的必需项目数 / 需要证据的项目总数；路径、行号、原文、命令结果须可由 root 复核。验收清单须至少包含一项证据要求。 |
| 范围遵守 | 15 | 完全符合范围与输出约定 15；仅输出格式或数量超限、无需额外调查 10；发生非必要的越界只读调查 5；未经授权修改、越权操作或泄露凭证 0，并触发硬性失败。 |
| 返回速度 | 10 | T ≤ B 得 10；B < T ≤ 1.5B 得 5；T > 1.5B 或超时得 0。依据实际时间，不以回复字数或主观感受评判。 |

判定规则：

- 85–100 分且正确性至少 32 分、没有重大问题：可采用；必要的项目验证仍须通过。
- 70–84 分或正确性不足 32 分：需修正；root 判断是否值得追问，追问作为同一任务的新一轮独立记录。
- 低于 70 分：不采用，由 root 或原有对应子代理接手。
- 重大问题包括：会误导主任务的关键错误、伪造路径/运行结果、未经授权的修改或操作、凭证泄露。即使总分高也判失败，暂停该类任务派发并由 root 评估；记录实际维度分数和失败原因，不靠改分掩盖问题。
- 入口失败、纯环境故障或用户取消且没有可评交付时，质量及总分写 N/A；照常记录耗时、原因与收尾状态，计入可用性统计。已有部分交付则按清单评分并标明未完成。证据暂不可核验时先报待核验，完成检查后补发评分。
