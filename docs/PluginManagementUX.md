# 插件管理页面

## 范围与结构

本页优化仅作用于 FullUI。iOS/macOS 的分组行参考 SwiftUX MCP 的 [Settings List with Sections](https://www.swiftux.app/uicomponents/settings-list-with-sections)：同一插件行通过状态切换操作，分组容器负责层级，沿用宿主语义颜色和原生控件。tvOS 使用宿主已有的原生卡片按钮与导航结构，不采用网页预览中的下划线分页样式。

- 更新概况置顶：待更新数量、已安装数量、订阅源数量、全部更新与检查更新。
- 已安装插件与可安装插件分组展示。行内显示名称、版本、登录要求及操作；待更新版本使用箭头连接，避免以红色暗示旧版本出错。
- 订阅源显示可识别的主机名、完整地址及独立的健康状态。
- iOS 使用原生分组列表；输入订阅源移至添加面板。
- macOS 使用紧凑分组表单；卸载收进插件菜单。管理页获得焦点时提供“插件”菜单，全部更新为 ⇧⌘U，检查插件更新为 ⇧⌘R。
- tvOS 使用独立的 FullUI 页面：页头直接显示标题、安装/更新数量和原生操作按钮；已安装、可安装插件分别使用 `LazyVGrid` 与 `.buttonStyle(.card)`，沿用系统焦点放大和遥控器导航。优先展示插件自带图标，缺失时使用名称首字；已安装条目不再重复显示“已安装”。
- tvOS 的“订阅源”按钮通过 `NavigationStack` 打开独立页面，管理来源、重试及添加入口都在该页。返回键先回到插件网格。更新中保留顶部更新按钮的身份和焦点，操作由运行状态阻止重复执行；失败原因和重试入口仍保留。
- 原有 tvOS ShellUI 安装引导仍使用原来的管理视图。共享更新组件只由 FullUI 主动调用。

## 更新行为

`PluginSourceManager.updateAllPlugins(pluginIds:)` 只接受当前已安装且远程版本更新的条目。它在开始前快照候选版本，预留整个队列，复用现有 updater 的安装、激活、last-good、保留 pinned 版本和失败回滚路径。不会把“全部更新”解释为“全部安装”。

`PluginUpdateBatch` 在 MainActor 上串行处理队列：

1. 同一批次按插件 ID 去重；正在执行时拒绝另一个批次。
2. 行状态区分等待、更新中、已完成和失败。
3. 单项失败保留原因并继续处理后续条目；批次结束后显示成功/失败数及重试失败项按钮。
4. 取消时停止剩余队列并释放运行状态；已完成结果仍保留。
5. 进度由 source manager 持有，离开页面不会丢失或重新开始更新。主动检查更新时清除上一批结果。
6. 三端结束后刷新插件可用性、运行时能力与会话；tvOS 同时同步 App Group。

订阅源失败保留在对应源的状态里；批量更新失败保留在批次和对应插件行中，不写成“插件源异常”。

## 验证

- 新增批次测试覆盖失败后继续、去重、重复调用、仅重试失败项、空请求保留结果、任务取消和 updater 返回取消。
- 2026-09-10：Xcode 27 RC 工具链的 Core 回归测试通过 21 项 / 6 个 suite，覆盖批次、目录操作、索引错误、可用性、有效登录版本与会话 vault。
- 各宿主的最终 workspace build 和安装后的设备检查以本次交付记录为准；编译通过不等同于完成了真实插件下载更新。
