# 短剧模式与播放页规划

## 系列首页与分集区间（2026年10月19日，实施中）

本轮核实测试插件1.0.6的公开清单与校验和匹配的脚本：系列内容通过既有`homeFeed`的多个普通房间分区返回，每一季仍是独立剧目。播放目录没有通用季级元数据，宿主不解析剧名或分区ID猜测季关系。先展示已有系列分区，点击某季沿用独立剧目的播放与进度；本轮不在播放器内虚构跨季选择器。

共享首页模型对实际选择版本声明`contentKind=shortDrama`的来源，保留全部已通过协议校验的非空分区及其顺序，复用三端既有分区标题、卡片和导航。普通直播仍按原来的个性化／主推荐策略展示。首页协议既有8分区、每区20房间的限制不变；这些上限不用于播放分集目录。

iOS 同剧可能同时出现在热门和系列分区，首页卡片与播放目标共同使用分区项的转场标识，避免多个来源共用房间 ID。该标识只控制转场，每次导航重设、退出清空；作品身份与进度仍按原规则管理，其他入口保留原默认行为。

播放器选集三端统一每20个实际目录项一个区间。连续集号显示“第21–40集”，非连续目录按序位显示“第21–40项”，各集保留原集号、ID、标题和播放顺序。分组只影响浏览，未截断完整目录；连播、进度文件与逐集恢复不变。

打开面板默认当前集所在区间，切区间仅浏览，点击具体集才播放。区间包含当前集时定位它，否则定位段首；手动浏览不受播放采样、面板展开收起影响，宽度变化保留浏览区间，关闭重开回当前集。20项以内隐藏区间控件。

## iOS 逐集续播与选集定位（2026年10月19日，iPhone 已验证、iPad 阻塞）

本轮先接入 iOS FullUI。每部剧以插件 ID 和剧目 ID 区分，每集沿用目录稳定 ID，分别记录播放位置、时长、完成状态及更新时间，同时保留本剧最后观看集。进度保存在本机 Application Support，不包含播放地址、请求头或凭证；本轮不接入跨设备同步，其他宿主维持原有行为。

再次进入时，恢复仍然存在且可播放的最后观看集及其进度；记录失效时回到第一可播集。选回未完成的集，恢复该集自己的位置；已完成的集重新打开从头播放，选择当前集保持位置。成功 seek 才更新记录，预览位置不作为进度；正常结束记录完成，错误和旧播放实例不能覆盖新集。

保存复用现有播放采样，约五秒节流写盘，并在暂停、切集、后台和退出前保存。每剧独立原子 JSON 文件；损坏或不可读记录不被空记录覆盖，写入失败保留旧文件与内存进度。恢复只针对匹配的播放 UUID 和播放器层，等待可播放及可 seek 后跳转，恢复前的零值不能覆盖历史；失败使用既有反馈及重试路径。

分集面板每次打开直接显示当前集；手动浏览后展开或收起不抢回滚动位置，关闭再开重新定位。保留既有48pt格高、8pt间距、20pt水平内边距、10pt圆角及当前集1.5pt描边。横屏验收发现安全区坐标混用导致右偏，由 Astra 实际修改面板的全窗口容器与原点，修复关闭按钮裁切；未更换网格或控件样式。

## macOS / tvOS FullUI 适配（2026年10月14日，实施中）

本轮补齐 macOS、tvOS；下文“iOS 首版、其他端后续”保留为历史阶段记录，不代表本轮范围。仅显式声明 `contentKind=shortDrama` 与 `episodeSelection=qualityList` 的已选择插件版本进入短剧，未知声明保持原路径。ShellUI、观看进度持久化及跨端续看不在本轮范围。

完整流程为：现有分类／列表／搜索／收藏或历史入口 → 在直播状态过滤和直播模型创建前判断短剧声明 → 拉取完整分集目录 → 第一可播集 → 独立点播播放器 → 选集／进度／倍速／自动连播 → 末集停止或当前集重播 → 返回原浏览上下文。目录解释、请求取消、迟到结果隔离及片尾事件消费由 Core 的短剧模型负责；窗口、遥控器焦点及实际播放器生命周期由宿主负责。iOS 本轮继续使用已有 FullUI 模型，不改变其页面和手势。

## 播放页布局

以 390×844pt 手机布局为设计基准，实际安全区来自系统。视频等比适配，完整保留字幕和画面；其他画幅留黑，不强制裁成竖屏。

顶部为返回和更多，按钮及玻璃背板均为 44pt。更多承载播放设置；已确认横向媒体还提供“横屏观看”文字入口，竖屏页面不放全屏图标。竖向视频完整等比适配并在视频区域底部对齐，下方独立实黑区承载细进度线、剧名及当前集信息，最底部为选集胶囊和右侧循环切速入口。横屏使用全窗口视频与可隐藏控制浮层，倍速固定右下角，退出先回到竖屏。旋转保持同一播放器、播放 UUID 和播放意图，不重新解析本集。

时间轴常态只显示 2pt 轨道，拖动时为 3pt 轨道和短定位标记，取消常驻圆球。可见轨道下缘到标题行、标题行到选集外缘各为 12pt；真实触控高 44pt，向视频借用的 12pt 区域排除画面手势。轨道绘制和首尾映射使用同一整宽坐标。控制区左右与物理底边使用相同边距，参考系统公开的容器圆角计算并限制在 8–22pt，无系统值时为 22pt；大圆角屏幕保留已确认的紧凑比例，不追求严格同心而产生过大空边。不硬编码示意图的屏幕半径，不重复叠加底部安全区；辅助功能字号允许信息行和控件自然增高。

拖动时在轨道上方显示目标时间和独立抽帧预览。预览帧保留实际时间，近似帧明确标注，取消、换集和离页丢弃旧请求；不通过 seek 主播放器或截取当前画面伪造目标帧。无法抽帧时保留正式 seek 并显示不可预览反馈。暂停 seek 保持暂停，取消不提交；从结束态回拖清理结束状态，播放中拖到末尾按连播设置结算一次。

HLS 使用独立、串行且有数量上限的 FFmpeg 预览批次，避免没有图像 rendition 时 AVFoundation 在整个拖动期间等待；其他可支持资源使用 AVFoundation。滑块触摸期间暂时阻止导航返回与模态交互关闭，结束或取消后恢复原设置。手动进入横屏后保持横屏方向，明确退出后回到竖屏；离页恢复进入前的方向策略。

当前依赖的 ME 播放器存在跳转时间整秒截断边界：精确回到 0 秒可能早于媒体真实起点。仅当这次 0 秒 seek 被底层拒绝时，通过公开 layer 接口重新打开同一已解析资源，保留播放器、UUID、请求配置和播放意图；确认新条目 ready 且实际暂停、可播放后才结算成功，不使用非零偏移假装回到开头。重开期间旧的无错误 EOF 被消费，真实错误仍进入错误页；离页、换集和取消结束等待。

选集与设置使用同一个 SwiftUI 底部模态面板，提供半屏与展开两档。iPhone 面板左右贴边、底部延伸到屏幕边缘，只保留顶部 28pt 连续圆角；内部内容保持 20pt 水平间距与底部安全区。面板使用单层系统 regular Liquid Glass，移除覆盖玻璃的实色背景；内部集数按钮保持普通填充。原生浮动 sheet 在当前 SDK 未提供竖屏横向 inset 清零接口，因此在 FullUI 播放页内实现贴边呈现，不修改全局系统外观。

选集包含约 60×84pt 海报、剧名、可播集数、插件提供的播放范围说明和数字网格。现有房间模型未提供剧情简介，首版不填造简介。390pt 宽采用五列，大字时减少列数并扩展面板高度。集数格仅显示数字，当前集用白色描边、播放标识及无障碍描述共同区分。点击遮罩、关闭按钮、顶部下拖和无障碍 Escape 均走同一关闭流程；播放层在模态面板打开时不响应触摸或无障碍焦点。播放器及其选集、设置面板统一维持深色，适应媒体观看环境。

## 连播与选集规则

| 操作或状态 | 行为 |
| --- | --- |
| 首次选择一部剧 | 从第一集自动播放 |
| 再次进入一部剧 | 首版从第一可播集开始；持久续看另行实现 |
| 点击画面 | 暂停或继续 |
| 上滑或下滑画面 | 下一集或上一集，仅在同一部剧内切换 |
| 当前集正常结束 | 自动连播开启时播放下一集；关闭时停在当前集结束态 |
| 打开选集 | 暂停播放，记录打开前播放状态 |
| 关闭选集 | 恢复打开前状态 |
| 选择另一集 | 关闭面板，从目标集起点自动播放 |
| 选择当前集 | 关闭面板，保持进度并恢复打开前状态 |
| 首集向前切换 | 保持当前集并提示已是第一集 |
| 最后一集正常结束 | 停在末集结束态，播放键重播本集，保留选集入口，停止自动推进 |
| 切集加载失败 | 保留目标集，提供重试与选集，不悄悄跳过 |
| 没有可播放剧集 | 显示空态和返回操作 |

上下滑手势只作用于视频区域，排除控制按钮、拖动进度和选集面板。提供无障碍上一集、下一集动作。减少动态效果时取消滑动过渡；减少透明度交由系统玻璃材质响应，实际可读性仍需设备验收。

## 首版插件契约

沿用现有 `getCategories`、`getRooms`、`search`、`getPlayback` 和 `refreshPlayback`，不另设内容来源分支。插件 manifest 显式声明：

```json
{
  "hostBehavior": {
    "contentKind": "shortDrama",
    "episodeSelection": "qualityList"
  }
}
```

两个字段均可选；仅以上两个值同时匹配时，iOS FullUI 使用短剧页。缺失、未知声明仍用现有页面，不按名称、录播状态或 URL 推断。路由读取共享 manager 实际选择版本的 manifest，保持 pinned 和 last-good 选择语义。旧端忽略新字段，继续使用原播放菜单。

`qualityList` 表示 `getPlayback` 恰好提供一条非空 CDN，其 `qualitys` 每项是一集。`qn` 为唯一的正集序，宿主升序展示并保留间隙；下一集为返回目录中的下一项。空目录显示空态，多条非空 CDN、重复或非法集序显示契约错误，不截断数据。稳定身份包含插件 ID、房间 ID 和集序，媒体 URL 与标题变化不改变身份。

每项提供有限媒体的 `playbackHints.isLive=false`；播放地址、请求头、解密参数及不透明 `requestContext` 保持现有协议。选择时通过 `RoomPlaybackPreparer` 执行已有 `refreshOnSelect` 行为。原目录项保留刷新声明，刷新结果仅用于本次播放；失败不回退旧集或跳过目标集。

Core 拥有目录解释与结束事件策略；iOS 主 actor 模型拥有解析请求、选择和页面生命周期。切集取消旧请求，以 generation 拒绝迟到结果；每次播放使用新 UUID 和独立 coordinator，以 UUID 拒绝旧层结束回调。仅无错误的 `onFinish` 推进，结束重复事件只消费一次。面板打开时暂存结束事件，关闭后按连播开关处理；离页取消全部待处理工作。

播放器复用 `KSCorePlayerView`、`KSPlayerSessionConfigurator` 和 `KSPlayerPlaybackSession`，每集应用独立 options 与完整请求参数。现有直播恢复协调器不参与短剧续集。首版只声明实际实现的全局能力，不提供后台播放或画中画承诺。

后续独立设计 iPad、macOS 和 tvOS 的浏览与选集布局，并分别验收；不把手机手势直接复制到其他平台。

## 交互修订验收标准

此前验证覆盖播放和静态面板，没有证明拖动跟手、回弹及切换的连续性。以下修订由 Astra 定义，Luna max 实现；构建与设备验收完成前不视为通过。
