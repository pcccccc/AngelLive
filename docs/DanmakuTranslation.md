# 弹幕翻译

## 使用方式

FullUI 的“设置 → 翻译与字幕”增加“自动翻译弹幕”。默认关闭，与房间标题开关独立；两者共用目标语言、翻译引擎和用户配置的兼容 AI 接口。iOS／macOS 可用 Apple 原生翻译或大模型，tvOS 使用大模型。

自动翻译固定处理英语、日语和韩语，Apple 原生与大模型使用相同的来源语言范围；其他语言保留原文，不发起翻译请求。成功时展示译文；不确定语言、相同语言、翻译失败或来不及翻译时保留原文。图片表情、昵称和颜色保持不变，图文消息只翻译文字片段；某个片段未成功时仅保留该片段原文。已显示的历史消息不重新翻译。

大模型只接收需要翻译的文字片段，不附带昵称字段或图片 URL。API Key 继续使用现有本机 Keychain 配置，不进入插件、日志、同步或仓库。开启弹幕翻译可能增加服务用量。

## 接入与生命周期

共享翻译管线位于 `AngelLiveCore/Translation`，每个房间 ViewModel 持有独立的交付队列。三个 FullUI 宿主在原文屏蔽词检查之后接入，译后消息再交给既有聊天列表与飞屏调度器；不修改 transport、插件协议或 ShellUI。

队列按接收顺序交付，每条最多等待 3 秒。最多保留 128 条待交付消息，超出时让最早待处理消息回退原文，防止消息积压。Apple 原生与大模型请求分别计数：原生最多 64 个在途，不限制每秒请求数；大模型仍最多 2 个在途、每秒最多新发起 1 个请求。缓存最多 200 项；重复文本复用缓存或正在进行的工作。超出额度时保留原文，不另建重试队列。上述限制控制客户端请求频率，不代表服务商费用上限。

弹幕使用独立的语言识别入口：仅包含韩文字母的短句也识别为韩语，允许夹带数字、标点和表情。其他文字仍使用系统语言识别及置信度门槛；标题保留原来的保守识别规则。

切房、断连或退出时取消并丢弃未交付工作；进入后台停止新增翻译，恢复前台后处理新收到的消息。旧房间或旧配置的译文不得覆盖当前内容。原生语言资源仍由系统管理，不在原生失败后自动切换付费服务。

原生自动翻译先检查语言资源，只有已安装时才进入翻译队列。设置的“语言包”分组固定列出英语、日语和韩语到当前目标语言的语言对，排除与目标相同的语言，不依赖先遇到对应标题或弹幕。进入页面及切换目标语言时只读检查资源，分别显示检查中、已下载、下载或当前系统不支持；不再动态发现或追加其他语言。只有用户点击“下载”或“测试翻译”才允许请求系统下载界面。下载完成后重新检查资源状态，不把系统准备调用返回直接视为安装完成。

同语言、同用途的原生请求每批最多 32 条，使用请求标识匹配响应。iOS／macOS 26 及以上自动翻译使用 `installedSource` 会话，禁止自动请求下载；26.4 及以上优先使用已安装的 `.lowLatency` 资源，否则使用已安装的系统默认资源。检查与会话使用同一策略，按语言对和策略分别缓存状态。显式下载仍准备低延迟资源，并单独核验该策略是否安装成功，不能由默认资源已安装推断下载完成。旧系统使用安装状态预检后执行绑定界面的会话；若资源恰好在预检与调用之间被外部删除，旧系统公开 API 不能保证消除这段竞态。

接口返回认证错误或服务端限流后，当前配置暂停新弹幕翻译，继续显示原文。修改配置、切换开关或显式点击“测试翻译”可重新尝试；不在弹幕到达时反复重试同一个错误。
