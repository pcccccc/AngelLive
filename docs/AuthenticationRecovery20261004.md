# 请求认证失败后的登录恢复

## 问题与范围

分类、房间列表、搜索和播放请求已经能返回标准认证错误，但宿主的恢复入口不完整：部分按钮只切到通用设置并丢失平台身份，部分入口没有登录按钮；关键词搜索会吞掉各插件的认证失败，分享解析也可能被后续普通失败覆盖。

本次统一 FullUI 的恢复链路，使用当前已安装插件声明的现有登录页面和登录方式。生产插件、manifest 与插件协议无需修改。ShellUI 的原有入口及搜索 API 保持原调用方式。

## 实现

- 已知分类或房间入口通过宿主目录将 `liveType` 解析成真实 `pluginId`，在当前页面呈现账号恢复界面。
- 搜索新增显式 outcome API，同时返回成功房间及宿主捕获的认证失败插件 ID；插件错误文本和 context 不能决定登录目标。
- 单个目标进入其登录方式；多个或无法确定的目标由用户选择。插件不存在或没有本设备可用登录方式时说明原因，保留关闭操作。
- 恢复入口按插件实际支持的方式重新登录，避免过期的“已登录”状态强制走网页登录。
- 网页恢复入口显式打开登录网页，使用本次登录专属的临时网站数据存储，防止旧网页 Cookie 再次被采集；不清空原网站缓存或已保存凭据。正常设置页仍保持原行为。
- 部分搜索成功时保留结果并展示登录提示；下一页认证失败也不遮盖已有房间。旧任务不能回写新搜索的认证状态。
- 登录浮层关闭后仍在原错误页面，由用户手动重试；关闭浮层不视为登录成功。
- iOS/macOS 使用当前房间上的 sheet 呈现登录；房间真正离开时仍执行原有的播放器、弹幕及诊断清理，不因账号浮层存在而跳过清理。
- iOS UIKit 房间列表观察自身分类的最终房间、错误与加载状态。父级预载占用同一分类请求时，重复调用会提前返回；此前列表只在自己的调用返回时刷新，可能永远遗漏稍后到达的认证错误。现有错误也不会被列表初次显示时的重复请求清除。
- macOS 取流失败同步推进播放器显示状态，避免错误已经返回而界面仍停留在“获取播放地址”。普通重试进入加载，失败或空播放源进入错误，有效播放地址清除旧错误；静默恢复失败仍保留播放器界面。
- tvOS 分类加载失败后重试重新获取分类；播放认证失败后重试重新取流。切换到播放错误页不提前结束房间会话。
