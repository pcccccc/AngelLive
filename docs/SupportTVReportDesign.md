# TV 诊断报告与分享页面

用户在录制态修改后再次指出报告页仍有明显视觉问题。选择先处理录制只表示顺序，不能把报告、编辑和分享留作整条流程的永久缺口。本轮补齐 TV FullUI 的这些状态，服务、报告格式、iOS/macOS 和 ShellUI 不变。

## 视觉参考与规格

参考现有 `TV/AngelLiveTVOS/Source/Setting/SettingView.swift` 的菜单，以及刚完成验收的 TV 录制页。实包 tvOS 27.0 / 1920 × 1080：普通单行操作为 830 × 66 pt，聚焦为 838 × 74 pt。布局必须复用现有 `SupportDiagnosticsTVOperationRow` 的原生 Button、body 文字、尾部符号、15 pt 行间距，不给某个操作另设宽高或大号样式。

实包验证发现不同 SF Symbol 的固有高度会把同一原生行分别撑到 70.5 pt、67 pt。尾部符号应使用不参与文字行高计算的 overlay，并为文字预留图标空间；按钮尺寸仍由系统样式与正文决定，不能只复用同一个 Button 组件就宣称同高。

所有 TV 诊断主屏采用同一半屏比例：左列水平内边距 90 pt；右列宽为可用容器一半减 50 pt；两列用最近 ScrollView 的 containerRelativeFrame。外层横向 padding 为 0、纵向 60，移除旧报告态 1400 pt / 72 pt 额外限制。标题使用已经实测通过的原生 principal 标题组件。录制页布局与交互保持本轮开始时的版本。

## 报告就绪

```text
                    问题诊断与反馈
┌ 左：报告摘要 ──────────────────┬ 右：与设置页一致的操作行 ───────┐
│ 报告已生成                      │ 检查并分享报告               > │ 初始焦点
│ 生成时间          记录时长       │ 补充／编辑问题描述           ✎ │
│ 09/18 14:14       3:21          │ 重新记录                    ↻ │
│ 操作记录          调用记录       │ 清除报告                    ⌫ │ 仍先确认
│ 0                 0             │                               │
│ 未采集到复现操作时的简短说明。    │ 先检查内容，再自行分享。         │
│                                │                               │
│ 问题描述                        │                               │
│ 尚未补充／最多三行摘要           │                               │
└────────────────────────────────┴───────────────────────────────┘
```

- 删除 TV 的三步骤进度条、重复成功勾、主屏输入框与保存按钮。
- 主标题 largeTitle semibold；元数据为固定两列两行 Grid，标签 caption secondary、数值 body/callout；不再依赖 ViewThatFits 把四组数据退化成一条长竖列。
- 空采集与错误快照都如实描述，不做成功采集的暗示。错误详情可提供最多三行摘要，完整内容仍在报告中。
- 问题描述主屏只展示摘要；为空显示「尚未补充」。description 与 savedDescription 不同时标明未保存。
- 右列四个动作使用同一操作行组件，默认聚焦预览；重录和清除沿用现有确认，不立即执行破坏性操作。确认弹窗的取消应回到对应按钮。

## 补充说明

- 从操作行打开 TV 独立 fullScreenCover 编辑页；左右比例与其他诊断屏一致，标题「问题描述」。主屏不再承载键盘入口 TextField。
- 左侧简短说明需补充发生时间、操作和现象；右侧系统 TextField 使用 body，进入编辑页时先聚焦输入框，激活后交由 TV 原生全屏键盘输入，其下是同宽原生「保存并返回」「取消」操作行。
- 编辑器持有本地 draft；取消尚未保存的修改不写入上层。保存回调 `(String) -> String?` 返回 nil 代表成功，错误字符串则保留编辑器与输入并就近显示错误。
- root 的 TV 保存闭包校验所捕获报告 sessionID 仍为当前且未在录制，随后更新 description 并调用原 saveDescription；错误时保留既有 dirty draft 契约，不能把 service 的内存更新当成磁盘保存成功。TV ReportPhase 用报告 sessionID 作为 identity，报告更换不能沿用旧编辑器。
- 保存成功通过编辑页关闭和报告摘要更新表达，不再在 TV 根视图铺设绿色成功条挤压双栏；不增加自动保存、网络提交或服务 API，真实磁盘错误文案必须保留。

## 预览与手机下载

- TV 预览与描述编辑一样使用独立 fullScreenCover 内的 NavigationStack，按系统根页面的安全区域布局。实包比较发现 navigationDestination 的预览会比报告、编辑页多出 80 pt 列宽；不能仅复用按钮组件就视为宽度一致，也不单独给某个按钮补硬编码宽度。
- 左列显示完整报告及可用遥控器浏览的文本区域，保留真实原文、不截断报告。右列仍为相同尺寸的原生操作行，初始提供「用手机下载报告」「返回报告」。
- tvOS 的正文使用原生只读 `UITextView` 桥接，阅读视口高 520 pt，保持单宽 footnote、16 pt 内边距和原有底色。`isSelectable` 让控件参加 TV 焦点系统，保留系统的滚动与文本无障碍语义；不要将整篇长 `Text` 设为一个 SwiftUI 焦点，实包已确认这只能聚焦、无法向下浏览。桥接仅在报告内容改变时更新文字并回到顶部，不因焦点切换重置阅读位置；iOS/macOS 保持原实现。
- 用户明确激活手机下载后才开始既有局域网服务。操作行切换为「关闭手机下载」，下方呈现二维码与同一网络、五分钟有效期的说明；错误时给同宽「重试」行和原服务错误。
- 返回报告、离开预览、报告变化、开始录制及关闭手机下载都保留现有 stop 语义。遥控器 Menu 在下载展开时先关闭下载，否则返回报告。
- 返回处理属于诊断根页面及当前预览，设置和错误页的外层 NavigationStack 不应再注册直接关闭整个诊断窗口的 Menu 回调；实包已观察到这种外层处理令预览越级退到设置。
- 分享与编辑页也使用语义清晰的 principal 标题，不能再显示低对比系统标题。
